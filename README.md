# Арена переговоров

MVP-тренажёр деловых переговоров. Состоит из двух модулей в одном приложении:

- **Обучение** — уроки с теорией и встречей с AI-собеседником текстом и голосом (`?screen=lessons`, открывается по умолчанию);
- **Тренировки · Стол переговоров** — пошаговая мини-игра с картами действий и AI-поставщиком (`?screen=table-settings`, см. [раздел ниже](#мини-игра-стол-переговоров)).

Разделы связаны через боковое меню: «Тренировки» в уроках ведёт на стол, «Обучение» на столе — к урокам.

| Модуль | Клиент | Сервер | Общие типы |
| --- | --- | --- | --- |
| Обучение | `src/screens`, `src/components`, `src/hooks`, … | `server/index.ts` | `shared/lesson-opportunity.ts` |
| Стол переговоров | `src/table/*` | `server/table/*` (маршруты подключаются в `server/index.ts`) | `shared/table/*` |

## Что реализовано

- интерфейс переговоров по референсу: этапы, диалог, персонаж, задача и блок наставника;
- текстовый чат с YandexGPT и сохранение контекста открытой сессии;
- запись голоса по первому нажатию и остановка по повторному;
- распознавание записи через Yandex SpeechKit с подстановкой текста в поле ввода;
- голосовое сопровождение контрагента: реплики директора озвучиваются через Yandex SpeechKit TTS и показываются субтитрами;
- экраны на десктопе свёрстаны по эталону 1920×1080 и масштабируются целиком с сохранением пропорций макета;
- адаптивная вёрстка для настольных и мобильных экранов;
- ключи Yandex Cloud используются только на сервере.

Кнопки сценария, подсказок, паузы и завершения пока работают как минимальные интерактивные заглушки.

## Стек

- React + Vite + TypeScript;
- Tailwind CSS и компоненты в стиле shadcn/ui;
- Node.js + Express + TypeScript;
- YandexGPT;
- Yandex SpeechKit;
- MediaRecorder API и ffmpeg.

## Запуск

Требуются Node.js 20 или новее, API-ключ сервисного аккаунта и идентификатор каталога Yandex Cloud.

1. Создайте в корне проекта файл `.env`:

```env
YANDEX_API_KEY=your_api_key
YANDEX_FOLDER_ID=your_folder_id
API_PORT=3001
# необязательно: голос и скорость озвучивания директора
YANDEX_TTS_VOICE=ermil
YANDEX_TTS_SPEED=1.0
```

2. Установите зависимости:

```powershell
npm.cmd install
```

В PowerShell используется `npm.cmd`, потому что системная политика Windows может блокировать `npm.ps1`.

3. Запустите frontend и backend:

```powershell
npm.cmd run dev
```

4. Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173).

Vite перенаправляет запросы `/api` на Express-сервер по адресу `http://127.0.0.1:3001`.

## Голосовой ввод

1. Выберите режим `Голос`.
2. Нажмите круглую кнопку микрофона и разрешите браузеру доступ к микрофону.
3. Произнесите фразу.
4. Нажмите кнопку повторно.
5. После распознавания текст появится в поле ввода, где его можно исправить и отправить.

Схема обработки:

```text
Микрофон -> MediaRecorder -> Express -> ffmpeg -> Yandex SpeechKit -> поле ввода
```

Этот вариант не зависит от Web Speech Recognition и поэтому подходит браузерам, где `SpeechRecognition` отсутствует, включая Opera. Для доступа к микрофону страница должна быть открыта через `localhost`, `127.0.0.1` или HTTPS.

## Голос контрагента

После нажатия «Начать практику» и после каждого ответа директор произносит реплику:

- аватар подсвечивается, в поле ввода — «Слушайте», голос, текст и подсказка временно недоступны;
- текст реплики сразу виден в блоке «Директор завода» (субтитры), в панель «Разговор» он попадает, когда директор договорит;
- «Пауза» и диалог завершения останавливают речь, «Продолжить» воспроизводит её с того же места;
- при ошибке синтеза встреча продолжается: реплика остаётся текстом, пользователь видит уведомление.

Схема: `YandexGPT → /api/speak → SpeechKit TTS (mp3) → Audio`.

## Отображение на десктопе

При ширине окна от 1101 px экраны рисуются на холсте 1920×1080 из макетов и масштабируются через CSS `zoom` (`src/lib/stage.ts`, `src/styles/stage*.css`). Полный отчёт прокручивается внутри холста. На узких экранах действует прежняя адаптивная вёрстка.

Экраны стола переговоров масштабируются своим компонентом `Stage` (`src/table/components/stage.tsx`) при любой ширине окна. Их базовые стили элементов (`body`, `button`, …) действуют только пока открыт стол: `TableApp` ставит на `<html>` класс `table-module`, а правила в `src/table/styles/base.css` ограничены им.

## Мини-игра «Стол переговоров»

Тренировка в формате пошаговой мини-игры: пять условий сделки на столе, шесть карт действий, жетоны уступок и AI-поставщик на YandexGPT (`yandexgpt-5-lite` — реплики поставщика, `yandexgpt/latest` — текст оценки; модели меняются переменными `YANDEX_CHAT_MODEL` и `YANDEX_REASONING_MODEL`). Путь: настройки → «Как устроен стол» → стол (до 8 ходов) → итог → краткий и полный отчёт → история тренировок.

Каждый экран сверстан на эталонном холсте 1920×1080. «Полный отчёт» — холст 1920×2620 с прокруткой. Графика (логотип, аватар поставщика, иконки карт, навигация, иллюстрации форматов) вырезана из SVG-макетов без изменений (`public/assets`, `src/table/assets`).

Экраны стола используют общий параметр `?screen=` с префиксом `table-`:

| Макет | Маршрут / состояние |
| --- | --- |
| T01 · Проверка настроек | `?screen=table-settings` |
| T03 · Бриф компактно (как устроен стол) | `?screen=table-howto&id=…&start=1`, кнопка «К брифу» открывает бриф встречи |
| T04 · Стол · старт | `?screen=table&id=…` |
| Стол · 04 · карта «Вопрос» | карта 1 (клавиша 1) |
| T06 · ожидание ответа | после «Сделать ход», пока поставщик отвечает |
| T07 · реакция и раскрытая карта | ответ открыл мотив: карточка мотива, «Вы узнали», +доверие и +очки |
| T08 · условная уступка | карта 4: «Мы готовы… если вы…», условия выбираются из списка |
| T09 · сборка пакета | карта 5 (и карта 2 «Якорь» в том же виде) |
| T10 · красная линия | пакет выше бюджета или гарантия меньше 24 мес. |
| T11 · не хватает жетонов | карта 4 при нуле жетонов |
| T12 · пауза / T13 · связь прервалась / T14 · подтверждение выхода | «Пауза», ошибка сети при ходе, «Выйти» |
| T15 · пакет согласован | карта 6 «Резюме» после принятого пакета |
| Стол · 15 · соглашение достигнуто / T16 · без сделки | `?screen=table-result&id=…` |
| T17 / T18 · Краткий отчёт | `?screen=table-report&id=…` (из истории — «Разбор») |
| T19 · Полный отчёт | `?screen=table-full-report&id=…` |
| История тренировок (пустая / заполненная) | `?screen=table-history` |

Логика стола:

- **Решения принимает сервер, модель только формулирует.** Скрытая карточка поставщика (`server/table/supplier-card.ts`) задаёт, что он может принять: 44 000 ₽ — только от 120 штук, полной отсрочки нет (мотив «График оплаты»), 7 дней — только при полной предоплате или по 48 000 ₽ (мотив «Срок производства»), 36 мес. гарантии — только по полной цене. Карточка не уходит в браузер.
- **Ход** (`POST /api/table/:id/turn`) детерминированно меняет стол: вопрос открывает мотив, якорь и пакет получают принятие или встречный пакет (ближайший приемлемый вариант), уступка при условии принимается, дополняется встречным условием или отклоняется. YandexGPT перефразирует ответ поставщика; если модель поменяла числа или потеряла условия, остаётся точная реплика из правил.
- **Жетоны**: каждый шаг ухудшения своей позиции стоит жетон; уступка без встречной ценности — «бесплатная» (доверие падает, оценка снижается). Отклонённая уступка жетон не списывает.
- **Идемпотентность**: повтор хода с тем же `clientEventId` возвращает тот же ответ — при обрыве связи «Повторить» не создаёт второй ход; до подтверждённого ответа карта и жетон не списаны.
- **Завершение**: «Резюме» после принятого пакета — сделка; после 8 ходов — итог по состоянию стола; «Выйти» — попытка не сохраняется как завершённая. Таймер — ориентир, он не обрывает тренировку.
- **Отчёт** (`POST /api/table/:id/report`): оценка 0–4 по наблюдаемым действиям выставляется правилами (рубрика навыка «Управление уступками», «Пакетные предложения» или «Работа с интересами»); YandexGPT пишет сильные действия, точки роста и вывод, при сбое модели используется детерминированный текст. «Другой достижимый пакет» считается по скрытым правилам поставщика.
- Столы хранятся на сервере в `data/tables.json`, история — в `localStorage` браузера.

## API

### `POST /api/chat`

```json
{
  "messages": [
    {
      "role": "user",
      "content": "Предлагаю обсудить условия запуска линии"
    }
  ]
}
```

### `POST /api/speak`

Принимает `{ "text": "..." }` (до 4000 символов) и возвращает `audio/mpeg` с озвученной репликой директора. Повторные запросы одного текста обслуживаются из кэша сервера.

### `POST /api/transcribe`

Принимает `multipart/form-data` с файлом в поле `audio`. Максимальный размер записи - 8 МБ.

### Стол переговоров

`POST /api/table/start`, `GET /api/table/:id`, `POST /api/table/:id/turn`, `POST /api/table/:id/time`, `POST /api/table/:id/finish`, `POST /api/table/:id/report`.

## Сборка и тесты

```powershell
npm.cmd run build
npm.cmd start
npm.cmd run test:unit
```

После сборки Express раздаёт содержимое каталога `dist` на порту `API_PORT`. `test:unit` запускает тесты уроков (`tests/*.test.ts`) и правил стола (`tests/table/*.test.ts`).

## Безопасность

- `.env` и `data/*.json` исключены из Git;
- входные данные ходов стола проверяются и ограничиваются на сервере;
- ключи не попадают в клиентский JavaScript;
- сервер ограничивает размер текста, число сообщений и размер аудиофайла;
- если ключ когда-либо был опубликован, его необходимо отозвать и создать заново.
